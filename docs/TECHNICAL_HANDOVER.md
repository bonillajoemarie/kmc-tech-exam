# Technical Handover — Support Ticket Management App

Operational notes for whoever runs this app next. For architecture, features, quickstart, and the realtime contract, see the root `README.md`; for the original build plan, see `docs/superpowers/plans/2026-08-17-support-ticket-app.md`.

## Running locally

1. Start MySQL (db `kmc_tickets`, `root`, empty password) and Redis.
2. **Backend:** `cd backend && composer install && cp .env.example .env && php artisan key:generate && php artisan migrate:fresh --seed && php artisan passport:keys --force`, then `php artisan octane:start --server=frankenphp --host=0.0.0.0 --port=8000`.
3. **Frontend:** `cd frontend && npm ci && cp .env.example .env && npm run dev` → http://localhost:5173 (Vite proxies `/api`, `/broadcasting` → :8000 and `/apps` → Reverb :8080).
4. Reverb runs **co-located with the backend** — inside Docker it is a second supervisord process in the *same* container (Octane :8000 + Reverb :8080). Locally, start it in a second terminal with `php artisan reverb:start --host=0.0.0.0 --port=8080`. Do not set `BROADCAST_CONNECTION=log` (see Gotchas).
5. Admin panel: http://localhost:8000/admin → `admin@example.com` / `password`.

## Key design decisions

- **Reverb co-located with the backend, not inside Octane** — in Docker, one container runs *two* supervisord programs: `octane` (HTTP :8000) and `reverb` (websocket :8080). Locally they are two processes. The frontend `laravel-echo` client (pusher protocol) talks to Reverb; `/broadcasting/auth` is a Laravel route served by Octane.
- **Standalone exam app — the FlowerStore tenant read-only DB invariant does NOT apply here.** The backend connects directly to `kmc_tickets` with full read/write; there is no multi-tenant split, no SSH-tunneled read-only access, and no outbox/dedup gateway. Ordinary Laravel controllers write straight to MySQL.
- **Passport for API auth** — customers authenticate with personal access tokens (`HasApiTokens`, Bearer header, `auth:api` guard in `config/auth.php`). The Filament panel uses the session `web` guard and is restricted to the `admin` role.
- **API versioned under `/api/v1`** — resource routes live in a `v1` prefix group in `routes/api.php`; the React client targets `/api/v1/*` through the `/api` dev/prod proxy. `/broadcasting/auth` is intentionally unversioned (it is Reverb's own route).
- **Realtime over private channels** — `private-user.{id}` (ticket owner) and `private-staff` (admin role), authorized in `routes/channels.php`; auth happens through the `auth:api`-protected `/broadcasting/auth` endpoint proxied by Vite.
- **Notification persistence via localStorage per user** — `NotificationContext` stores read/unread state under `supportdesk.notifications.{userId}` (cap 50); there is no server-side notification table.
- **Dedup via `comment_id`** — the client keeps a `seen` set per session and skips self-authored events (`author_id === user.id`), so a comment you post yourself doesn't ping you. Internal comments are filtered server-side before the event is even fired.

## Known gotchas

- **Never set `BROADCAST_CONNECTION=log` in a real run.** It is only correct inside CI/tests (`phpunit.xml` and the CI step use `log`/`null`). With `log`, the event is written to the log instead of being pushed, and the frontend will appear dead. `.env.example` ships `reverb`.
- **The DB is MySQL `kmc_tickets`**, not SQLite. `phpunit.xml` overrides to `sqlite :memory:` for tests only. If `migrate:fresh --seed` fails with a SQLite driver error, the `.env` is pointing at the wrong DB.
- **Seed users/roles are load-bearing.** The `admin`/`customer` roles and the demo users (`admin@example.com`, `customer@example.com`, `jane@example.com`, all `/ password`) come from `DatabaseSeeder` + `TicketLookupSeeder`. Reseeding wipes ticket data; roles are recreated via `findOrCreate`.
- **Tests will refuse to touch a real DB.** `tests/TestCase::setUpTraits()` aborts the suite unless `DB_CONNECTION=sqlite` with `DB_DATABASE=:memory:`. This is a hard guard against `RefreshDatabase` `migrate:fresh`-ing the MySQL dev DB if `phpunit.xml` is bypassed or overridden. If you ever see "Refusing to run the test suite", check how env vars are being forced.
- Reverb **keys must match** between backend `REVERB_APP_KEY` and frontend `VITE_REVERB_APP_KEY`; a mismatch silently disconnects websockets.
- The `frankenphp/Caddyfile` (Octane's server stub for the container) lives in `backend/frankenphp/` and is committed. The old ~167 MB gitignored FrankenPHP **binary** at that path was deleted (it was a glibc build that cannot run on Alpine; the Dockerfile downloads the static musl asset instead). `.gitignore` keeps `frankenphp/*` but whitelists `frankenphp/Caddyfile`.

## Troubleshooting

- **Frontend shows no realtime updates / notifications never arrive** → check `BROADCAST_CONNECTION=reverb` in `backend/.env`, then backend `REVERB_APP_KEY` == frontend `VITE_REVERB_APP_KEY`; confirm Octane is running on :8000 and the Vite proxy is up (dev) — the `/apps` ws proxy targets :8080.
- **`/api` requests return 401** → token missing/expired; log out/in. Passport keys missing → run `php artisan passport:keys --force`.
- **`Connection refused` on :8000** → Octane not started or `APP_URL`/proxy host mismatch; the Vite proxy expects `127.0.0.1:8000`.
- **Tests fail locally but pass in CI** → CI runs Pest against SQLite `:memory:` with `array`/`sync`/`log` overrides; reproduce with `php artisan test` after `cp .env.example .env` (test env comes from `phpunit.xml`).
- **Redis errors** → confirm `phpredis` is installed and Redis is up; all of cache/queue/session/broadcast depend on it.
- **Filament panel redirects/denies login** → the `admin` role is required; re-seed to restore it, and log in with `admin@example.com`.

## AI tooling used in this build

The whole app (plan Tasks 1–4 + Revision 1) was built interactively with the **opencode CLI**, mostly by delegating well-scoped work to subagents. The models actually used (audited from opencode's session database, `~/.local/share/opencode/opencode.db`):

| Model | Provider | How it was used |
|---|---|---|
| `deepseek-v4-flash-free` | opencode | **Primary model.** The main agent and the majority of subagents: backend REST API (Task 2), Filament admin panel (Task 3), React customer frontend (Task 4), seeders/factories/Passport, Reverb events + attachments API, Filament realtime + attachments, frontend ESLint + Echo + uploads, the final Pest-native test conversion, the notification-bell feature, the Docker + pm2 infra, and the docs. |
| `nvidia/nemotron-3-ultra-550b-a55b:free` | OpenRouter | One "Pest 4 conversion + coverage" subagent attempt — output was unusable and discarded. |
| `google/gemma-4-26b-a4b-it:free` | OpenRouter | First PHPUnit→Pest conversion subagent attempt — unusable and discarded. |
| `nvidia/nemotron-3.5-lightning:free` | OpenRouter | A supporting main-agent session during the build. |

Notes:

- Models ran with opencode reasoning `variant: max` (the heavy build tasks) or `variant: high` (the later subagents).
- The two early Pest-conversion attempts were redone with `deepseek-v4-flash-free`, which produced the current Pest-native suite (33 backend tests green) and removed the old `tests/Concerns/ApiTestHelpers.php`.
- This is a self-contained exam app — no model ever touched a production system, credentials, or real data.

## Difficulties encountered

1. **Vitest worker native crash (the hardest).** The new notification tests killed the vitest worker with an opaque `Worker exited unexpectedly` — a V8-level segfault, not a JS error. Bisection of the test files showed the root cause: the mocked `useAuth()` returned a **fresh user object on every render**, so `NotificationProvider`'s `useEffect([user])` re-ran → `setNotifications(...)` → re-render → infinite loop that blew the V8 stack. Fixed three ways: stable mock user via `vi.hoisted`, the provider is now keyed by `user?.id` in `App.tsx`, and the effect depends on `user?.id` instead of `user`.
2. **React 19 `act()` flushing.** Dispatching a mocked Reverb event outside `act()` left the state update unflushed, so `screen` still showed the previous count. Fixed by wrapping the dispatch helper in `act()`.
3. **Composite accessible names.** A notification item is a `<button>` whose computed accessible name is author + ticket number + message preview, so exact-match `getByRole('button', { name: ... })` failed; switched to regex substring matching.
4. **Two failed Pest-conversion subagent attempts.** Both the Nemotron-3-Ultra and Gemma-4 subagents returned broken conversions; the DeepSeek Pest-native rewrite succeeded.
5. **First Docker subagent produced nothing.** The initial "Docker + pm2" subagent returned zero files; the re-dispatched attempt built the full compose stack. During it: a stray ~167 MB gitignored glibc FrankenPHP binary blocked the `frankenphp/Caddyfile` directory (deleted), and the old `frankenphp` `.gitignore` pattern would have swallowed the Caddyfile on fresh clones (fixed to `frankenphp/*` + `!frankenphp/Caddyfile`).
6. **FrankenPHP glibc vs musl.** The developer's FrankenPHP binary is a glibc build that cannot run on Alpine; the Dockerfile downloads the static musl asset instead.
7. **Reverb wiring.** The dev `.env` originally had `BROADCAST_CONNECTION=log`, which silently disables realtime — `.env.example` now ships `reverb` while tests/CI keep `log`/`null`. Backend `REVERB_APP_KEY` must equal frontend `VITE_REVERB_APP_KEY` or sockets silently disconnect.
8. **Compose v5 CLI quirk.** `docker compose up --profile services -d` errors on compose 5.x; the flag must come before the subcommand: `docker compose --profile services up -d --build`.
9. **LSP false positives.** Pest's dynamic methods (`assertExists`, `forgetGuards`, `withoutMiddleware`), `Storage::url()`, and vendor Symfony type-hints show as editor errors but are not real failures — trust the CI gates, not the language server.
10. **Session interruptions.** The build hit its context limit mid-way (Pest conversion was left aborted); the working state was recovered from the opencode session DB before continuing.
